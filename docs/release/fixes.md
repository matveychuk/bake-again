# Bake Again — виправлення після фінального аудиту

Дата: 27.09.2026. Основа: [незалежний аудит](final-audit.md). Початковий аудит збережено без змін; SHA-256 зіставлено з копією на початку роботи. Виправлення накладено на наявну робочу копію, без скасування попередньої редактури, локалізації та SEO. Публікація, DNS, зовнішні налаштування Sites і доступ D03 не змінювалися.

**Поточний висновок:** D01, D02, D04, D05, D06 та локальна частина U01 виправлені й перевірені. Це не схвалення публічного запуску: D03 та зовнішня перевірка розгорнутої версії залишаються окремим релізним етапом. Не всі пристрої, зовнішні сервіси та можливі стани перевірено.

**Відтворення причин:** у збереженій копії початкового коду повторено D01 (100 г у структурованих інгредієнтах проти 50 г у тексті) і безумовне успадкування Tested у D04. D02 підтверджено старим пошуком лише в базовому рецепті та namespace композиції; D05 — точними рядками; D06 — старими plain-text відповідями й відсутністю локалізованого UI. Після виправлень браузерні сценарії виконано заново. [Порівняння до/після](fixes-evidence/before-after.json).

Візуальний контроль 200% тексту додатково виявив надмірне звуження кнопок і бейджа Cook Mode. Виправлено перенесення кнопок та елементів шапки; нижній відступ тепер враховує виміряну висоту фіксованої навігації, щоб вона не закривала кінець інструкції. DOM-перевірки без горизонтального overflow самі по собі були недостатні для цього висновку.

Додатково в межах D01/локалізації замінено старі англомовні інструкції Cook Mode Наполеона локалізованими канонічними кроками. Збережено альтернативи інгредієнтів (зокрема сметана або густий йогурт), 17 груп, ідентифікатори кроків і версію для відновлення наявних сесій; тепер кількості в інструкціях відповідають вибраному масштабу. Попередній аудит не виділив цей окремий прояв — його висновок про мовне покриття не слід вважати доказом відсутності цієї помилки.

## 3. URL, індексація та збережені дані

[Повна таблиця міграції](recipe-url-migration.md) містить 81 мовну пару старої й нової адреси. Для кожної пари застосовується також `/cook`. Публікаційний статус не змінювався: 22 published × 3 мови — 66 detail та 66 Cook Mode; 5 чернеток залишаються закритими в production.

- 150 базових публічних маршрутів × 390/900/1440 = **450 завантажень у Chrome**: HTTP 200, правильний `lang`, H1, alt, відсутність page errors і горизонтального переповнення. Це DOM-перевірка всіх маршрутів та візуальна вибірка, не ручний перегляд кожного пікселя.
- **194 HTTP-сценарії** зі старими адресами, стабільними ID, історичними маршрутами та 404; додатково перевірено кінцеві адреси чернеток. Змінені адреси одразу ведуть на canonical через 308, без другого перенаправлення. Cook Mode зберігає noindex.
- Після остаточних змін компонування повторено **всі 66 Cook Mode × 3 ширини = 198 завантажень** і **194 HTTP-сценарії** — помилок не зафіксовано. [Остаточний прохід Cook Mode](fixes-evidence/browser-cook-final.json).
- **78 sitemap-URL** перевірено окремими SSR-запитами: title, description, self-canonical, три hreflang. У 66 базових рецептів — Recipe JSON-LD; на 2× її немає. Sitemap має 78 унікальних кінцевих URL. Robots, персональні noindex і захист редакторських маршрутів збережено.
- Тестові збереження, покупки, записи випічки та Cook Mode створено функціями попередньої реалізації. Після переходу на нові URL три збережені рецепти ведуть на canonical у кожній мові; сирі покупки не змінилися й мають локалізовані назви; три Cook-сесії відновили крок 2. Перевірено збереження фрагмента старого посилання й кількості під час перемикання мови. Це вибіркова перевірка сумісності сховища, не всі історичні міграції.

Докази: [маршрути та HTTP](fixes-evidence/browser-routes.json), [SSR SEO](fixes-evidence/seo-http.json), [сумісність даних](fixes-evidence/persistence.json).

## 4. Функції, компонування та доступність

## 6. Невиправлене й неперевірене

**Невиправлене за умовою задачі:** D03 і пов’язаний зовнішній заголовок Sites. Перед публічним запуском потрібно окремо відкрити погоджений доступ, опублікувати перевірену версію й повторити анонімні перевірки endpoint, assets, перенаправлень, canonical/hreflang/Recipe та sitemap на основному домені.

**Не доведено цією роботою:**

1. Реальна індексація Google, Search Console/Rich Results Test, DNS/www, GitHub release variables та production-аналітика; відповідність зовнішнього deployment локальній збірці.
2. Реальна випічка перерахованих версій і точних пар із кремом; модель не створює доказів Tested.
3. Реальні телефони, Safari/Firefox, screen reader, повна WCAG/контрастна перевірка, усі touch/reduced-motion/200% text стани. Три ширини у Chrome не замінюють ці перевірки.
4. Закінчення довгих таймерів у реальному часі, фонові сповіщення/аудіо, hardware wake lock та повне офлайнове відновлення після закриття браузера.
5. Повний простір storage quota/відмов запису/пошкоджених даних і гонок між вкладками в інтегрованому браузері; всі історичні формати персональних записів.
6. Вичерпний перебір довільних чисел, дубльованих query-параметрів, пошукових синонімів і комбінацій фільтрів; усі 0,5×/1,5× стани кожного рецепта в браузері.
7. Live UI/API помічника, платні запити, upstream/streaming-помилки. Автоматизовані assistant-тести не є live перевіркою сервісу.
8. Повна редакційна перевірка п’яти чернеток та їхніх preview-станів. Нові slug не є дозволом їх публікувати.

Рекомендований наступний крок — окрема незалежна перевірка змін за цим реєстром; після неї — окреме релізне рішення щодо D03. Початковий аудит не переписано як «усе перевірено».
