## Brevo: повторно використати, а не створювати заново

- API DOI template **20**, active; sender/reply-to `hello@bakeagain.com`.
  Кнопка **`{{params.DOIurl}}`**, Advanced Tag **`optin`**.
  Відсутність `optin` спричиняла HTTP 400 `invalid_parameter`: active DOI template
  does not exist, хоча UI показував Active. Перевір цей tag перед переробкою HTML.
- Native hosted DOI template **5** збережений для звичайних форм. Не підміняй його
  продуктовим листом. Старі list **9** і templates **17/18** — історична реалізація
  млинців, а не схема для копіювання. Неактивні технічні клони не використовуй.
- Чинна підписка: `emailBlacklisted === false`, членство у підтвердженому мовному
  списку **4/5/6**, без відповідної відписки `listUnsubscribed`. List **3** або сам
  контакт не доводять підтвердження. Не реактивуй блокування/відписку.
- Native DOI через `/v3/contacts/doubleOptinConfirmation` записує Boolean
  `BA_LEAD_SIGNUP: true` перед входом до списків **3/4**. У generic welcome
  workflow **1**, умова кроку **7**: не в list9 І `BA_LEAD_SIGNUP` не заповнено.
  Це прибирає зайвий загальний welcome з тортом для продуктового запиту.
- Продуктовий лист надсилає спільний backend через `/v3/smtp/email`, а не нова
  окрема automation для кожного продукту. `headers.idempotencyKey` — стабільний
  UUID заявки; префікс на кшталт `recipe-...` спричиняв помилку формату.

Native DOI підтверджує згоду у Brevo. Return token сам не доводить згоду: backend
повторно перевіряє контакт. Токен у fragment URL, очищається й передається POST;
строк 24 години. Браузер зберігає лише `{magnet, until}` завершеного результату в
sessionStorage `ba_recipe_delivery_result`, без email/token. Refresh очищеної URL
не має показувати помилкове «прострочено»; без локального результату — нейтральне
«Перевір пошту».

Журнал має атомарний claim, захист повтору email+magnet протягом 10 хв,
ліміти 10/год на мережу, 8/день на email, 200/день сайт. Зберігання 7 днів з
прибиранням при наступних допущених заявках. Невизначену SMTP-відповідь не повторюй
безкінечно: поточний код зупиняє retry після 14 хв; спочатку перевір журнали провайдера.
Діагностика — лише дозволені коди/поля, не сирий provider message чи приватні дані.

## Поточний хостинг

Власний Cloudflare Worker **`bake-again`**, GitHub **`matveychuk/bake-again`**, `main`.
Застарілі `.openai/hosting.json` і Sites-проєкт не публікувати.
D1 binding **`ASSISTANT_QUOTAS`**, database **`bake-again`**.
Зашифрований секрет **`BREVO_API_KEY`** уже існує; значення не читати в журнал,
код, git чи документи. Для нового продукту він не потребує заміни.
Nonsecret runtime: `LEAD_MAGNET_ENABLED=true`, `BREVO_MAGNET_DOI_TEMPLATE=20`.
Існуючі Turnstile/службові секрети зберігай.

Поточний deploy pipeline застосовує D1 migrations перед Worker deploy. Звір
актуальну конфігурацію перед релізом. Wrangler CLI раніше не був авторизований;
не повторюй сліпі спроби входу, використовуй доступний погоджений шлях.
GitHub check іноді лишався In progress після Ready у Cloudflare: перевір реальне
розгортання й живу сторінку. Не роби серію зайвих push під час збірки.

## SendPulse: мінімальна гілка та збереження

Млинці перевірено з тригером Contains `млинці`, без урахування регістру,
на всі публікації, пауза повторів 5 хв, IG і FB окремо. Для нового продукту
узгодь охоплення з запитом: не копіюй «усі публікації» автоматично.

Приклад повідомлення (адаптувати до фактичного продукту):
«Привіт! 🥞 Надішлю тобі рецепт безглютенових млинців і картку юного кухаря одним
листом. Залиш email за кнопкою 👇». Кнопка «Отримати рецепт» → своя сторінка.

- Використовуй доступний конектор/API, якщо він достатній; інакше браузерний UI.
- Якщо є чернетка, **Cargar borrador**; не натискай **Eliminar borrador y continuar**
  без перевірки, що саме буде втрачено.
- Тип старої FB-кнопки «продовжити flow» не перемикався на URL. Після перевірки
  стану видали лише цю редаговану кнопку й додай нову URL-кнопку; не повторюй
  десятки однакових кліків і не видаляй історичні вузли без потреби.
- Вкладений **Guardar** кнопки → **Aplicar** повідомлення → верхній **Guardar**
  усього flow. Після цього перезавантаж і перевір. Apply не доводить серверне збереження.
- Перший URL-клік з коментарного повідомлення сам не відкриває вікно подальших
  повідомлень; не додавай залежний follow-up без перевірки правил платформи.
- У поточних млинцях tracking URL вимкнено; старі непідключені вузли збережено.
  FB має публічну відповідь, IG — ні. Не обіцяй їх однаковими без перевірки.
- Duplicate окремого блока був доступний. Наступна перевірка офіційної документації
  22.10.2026 підтвердила платне Copy flow; шаблони бібліотеки мають інші умови.
  Див. [API та копіювання](api-and-copy.uk.md), включно з межею публічного API/MCP.

## Що було реально перевірено

На дозволених адресах власниці: DOI → один лист млинці+картка; повторний DOI без
дубля; запит шоколаду тим самим підтвердженим контактом → окремий лист без DOI;
refresh callback коректний. Обидві бот-кнопки збережено й перечитано після reload.
Автотести й build пройдені. Коментар іншого профілю й відкриття/збереження на iPhone
на 22.10.2026 не перевірені. Не перетворюй цей знімок на доказ майбутнього запуску.
