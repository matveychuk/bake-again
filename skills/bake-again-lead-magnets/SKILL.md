# Bake Again — видача лід-магнітів

Переносний skill стандарту Agent Skills: основні інструкції та `references/`
не залежать від моделі чи конкретного застосунку. `agents/openai.yaml` — лише
необов'язкові метадані інтерфейсу OpenAI. Використовуй доступні в поточному агенті
інструменти файлів, команд і браузера; не припускай, що підключення або дозволи
іншого застосунку перенесені сюди. Для виконання потрібен доступ до проєкту Bake Again.

Повторно використовуй наявну систему: ключове слово → повідомлення з URL →
форма сайта → перевірка підписки → лист конкретного продукту.
Новим — після native Brevo double opt-in (DOI), чинним підтвердженим підписникам —
одразу. Кілька матеріалів одного продукту видавай кнопками в одному листі.

## Початок без повторного дослідження

1. Знайди корінь проєкту за `content/lead-magnets.json` та `package.json` у
   поточному workspace або підключеній папці; не покладайся на абсолютний шлях. Прочитай
   `AGENTS.md`. Для Instagram прочитай поточний стан, реєстр публікацій та
   пов'язаний запис у `docs/strategy/instagram.uk.md` / `docs/instagram/posts/`.
   У довгих журналах шукай релевантні розділи, не завантажуй усю історію.
2. Прочитай актуальний розділ **Recipe-specific PDF requests** у
   `lib/newsletter/README.md` і [перевірену реалізацію](references/implementation.uk.md).
   Реальні поточні налаштування мають перевагу над знімком у reference.
3. Витягни з запиту й файлів: назву, сталий ASCII ID, ключове слово, канали,
   готові матеріали/посилання, CTA, текст листа, пов'язаний допис і обсяг дозволених дій.
   Питай лише про відсутні суттєві дані; продовжуй незалежну підготовку.
4. Для текстів/продуктових рішень застосуй `bake-again-content`; якщо агент не
   виявив його автоматично, прочитай `skills/bake-again-content/SKILL.md` у проєкті.
   Для суто технічної
   зміни кнопки не підвантажуй усі його матеріали. Новий контент українською.

Режими: **обговорення** — без зовнішніх змін; **підготовка** — локальні матеріали й
перевірки; **налаштування** — дозволені запитом зміни та перевірка результату.
Не проси повторного дозволу на вже погоджені дії. Цей skill не переносить дозволи
з минулих чатів: створення ключів, розсилання тестів, публікація/планування допису
потребують відповідного дозволу в поточному контексті. Налаштування бота не є
дозволом опублікувати допис.

## Послідовність нового продукту

1. **Матеріали.** Збережи оригінали й окремі оптимізовані копії для видачі.
   Перевір зміст, розмір, відкриття та стабільні HTTPS-посилання. Для створення/
   редагування PDF спершу прочитай правила PDF з `AGENTS.md` і застосуй PDF skill.
2. **Сайт і лист.** Єдине джерело — `content/lead-magnets.json`: `page`, `email`,
   `bot`. Для майбутнього продукту додай один запис і його готові матеріали;
   виконай `npm run media:prepare`, потім `npm run lead-magnets:prepare`.
   Команда перевіряє файли й створює `outputs/lead-magnets/<id>.json` із готовими
   IG/FB текстами й URL. Інструкція — `lib/newsletter/lead-magnets.uk.md`.
   Маршрути, analytics, лист, підтвердження й Design Lab виводяться автоматично.
   Після одноразової міграції `0003` новий продукт не потребує нової міграції БД.
   Якщо запит лише про уніфікацію, не додавай нового реального продукту чи тригера.
   Не створюй новий API-ключ, DOI-шаблон чи паралельний backend для кожного продукту.
3. **Brevo.** Повторно використай перевірену native DOI-конфігурацію й окрему
   продуктову доставку. Перевір захист від загального welcome-листа, відписки й
   повторного відправлення. Ніколи не вважай саме існування контакту згодою.
4. **Реліз.** Виконай релевантні перевірки перед дозволеним розгортанням. Використовуй
   власний Cloudflare Worker; старі Sites-конфіги не є поточним місцем публікації.
   Дочекайся готового розгортання й перевір живу сторінку та файли до підключення CTA.
5. **SendPulse.** За офіційною перевіркою 22.10.2026 копіювання власного flow
   платне; готові шаблони без платних елементів доступні на Free. Публічні API/MCP
   запускають існуючі flow, але не мають документованого створення сценарію.
   Деталі й джерела — [API та копіювання](references/api-and-copy.uk.md).
   Звір актуальні можливості, якщо вони змінились. Якщо копії немає, створи мінімальну гілку з одним
   повідомленням і URL-кнопкою. Налаштуй тригер у кожному погодженому каналі.
   Збережи всі рівні редактора й після перезавантаження перевір текст, URL, ключове
   слово, охоплення публікацій та увімкнений стан. Див. пастки в reference.
6. **Доказ результату.** Пройди матрицю нижче, запиши лише підтверджене. Онови
   актуальні технічні й Instagram-записи; технічне налаштування не записуй як публікацію.

## Мінімальна матриця приймання

| Сценарій | Очікування |
| --- | --- |
| Новий дозволений тестовий email | Один DOI; до підтвердження продукт не надходить |
| Після підтвердження | Один лист потрібного продукту, всі його матеріали; без зайвого welcome |
| Чинний підтверджений підписник | Продукт одразу, без повторного DOI |
| Той самий підписник, інший продукт | Саме інший продукт, без DOI та підміни першого |
| Повторне натискання підтвердження | Без дублювання листа; коректний результат після refresh |
| Заблокований/відписаний контакт | Не відновлюється і не обходить перевірку згоди |
| Коментар з іншого профілю | Реальний тригер → правильне приватне повідомлення → форма |
| Матеріали на телефоні | Відкриваються через фактичні кнопки отриманого листа |

Перші сценарії перевіряй на дозволених тестових адресах, негативні й конкурентні
випадки — також на наявних автоматичних тестах. Не створюй реальну відписку
власниці для тесту без окремого погодження. HTTP 200, preview, увімкнений тригер
та API success не доводять доставку, спрацювання коментаря чи відкриття на iPhone.

## Економія контексту й звіт

Спершу використовуй цю карту, поточні файли й відомі причини збоїв. Не перечитуй
старий чат, не повторюй виправлені експерименти, не виводь великі DOM/логи.
Використовуй доступні достатні API/конектори; UI — коли потрібної можливості немає.
Після зміни потрібного фрагмента перевір його, а не весь акаунт. Не встановлюй
нові інтеграції лише заради цього skill. Актуальні правила сервісу, якщо потрібні,
перевіряй за офіційними джерелами.

Фінально коротко повідом: що налаштовано; що перевірено реально; що залишилось
неперевіреним і наступний крок. Не обіцяй відсоток економії токенів: skill скорочує
повторний пошук і діагностику, але не усуває налаштування нового продукту й QA.
